## Setting and notes

- Thinking is off (`enable_thinking: false`, no `reasoning_effort`) in every request of both legs, except the M3 thinking cell of models with speculative decoding, which sends `enable_thinking: true` only, so each template renders its own default effort. Without speculative decoding the thinking cell would repeat the 16K decode rate and is not run.
- Text-only: every screenshot is replaced by its text equivalent of equal token size (Qwen3.8 tokenizer), for every model.
- M4 headline = sum of TTFT over the 21 steps + 21 x 100 / R, where R is the run's decode rate (completion tokens / decode time over steps with server usage). The raw total mixes byte-identical prefill with each model's own output length, so a terser model would win it regardless of speed. Cap hits count `finish_reason=length` and streams cut inside a tool call (`incomplete_tool_call`), which still count as latency samples.
- Decode tok/s counts each model's own tokens. M3's output is a JSON array, where token counts are about equal across tokenizers; seconds per 100 tokens are given for the same reason. Prompt sizes are Qwen3.8 tokens ("16K" = 16,000); every result records the server's own `prompt_tokens`.
- Memory: server footprint of the oMLX process tree (`footprint`, RSS fallback); the system delta is wired + compressed + file-backed memory against the pre-launch baseline, so it also covers mmapped weights that the footprint leaves out.
- Cross-night band (old campaign): M1 and M3 up to ~20 %, M4 ~9 %. A ratio marked ≈ lies inside it and counts as no difference.
- Capability: solved = the checker passes within the 30-step budget (also after a wall timeout); runs excluded only for pipeline mismatches (model id, forwarded sampling or thinking). Anomalies (5xx, a reasoning leak with thinking off, a template fallback) count as that model's failures and are listed.
